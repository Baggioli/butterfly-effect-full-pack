## 访问

1. 在 Mac 的 Finder 中双击本项目的 `打开蝴蝶效应.command`。
2. 在终端中设置至少16位的应用访问口令，输入不回显。这是应用口令，不是 SSH 或 DGX 登录密码。
3. 浏览器打开 http://127.0.0.1:8787，用户名 `owner`，密码为刚输入的口令。

SSH 隧道在终端关闭后继续运行。若浏览器缓存了旧口令，使用无痕窗口重新登录。已有云端浏览器记录不会自动进入这个新地址；测试使用虚构人物，没有迁移或覆盖用户的真实记录。

## 当前运行方式

- SSH：使用本机已有的 `dgx` 配置和密钥，并保持主机密钥校验。
- DGX：`spark-864f`，独立目录 `/home/lq/apps/butterfly-effect`。
- Node：复用 `/home/lq/.nvm/versions/node/v22.23.3/bin/node`。
- Ollama：复用现有 `open-webui` 容器的本机接口 `127.0.0.1:11434`，实机版本 `0.34.2`。
- 默认模型：已安装的 `qwen2.5:32b`（Q4_K_M），没有下载新模型，也没有配置外部 API。
- 应用：用户服务 `butterfly-effect.service`，随用户服务管理器启动，失败自动重启，仅监听 `127.0.0.1:8787`。
- Mac：SSH 转发 `127.0.0.1:8787 → DGX 127.0.0.1:8787`。控制套接字位于 `/private/tmp/butterfly-effect-<本机UID>/dgx.sock`。
- 应用口令：DGX 用户状态目录中的独立文件，目录权限700、文件权限600，不在源码、聊天、日志或 Git 中。初次安装生成随机值，Mac 启动器允许用户安全替换。

没有修改现有 OpenClaw、Docker、Ollama 或 Tailscale 配置，没有扩大云端 Site 的访问范围。

## 真实模型结果

测试路径包含真实 HTTP 服务、口令认证、应用 API、本机 Ollama 模型元数据检查和实际推理；模型输出没有用模板或模拟响应替代。测试原始输入和输出均为虚构数据，保存在 `reports/`。

| 测试 | qwen2.5:7b | qwen2.5:32b |
| --- | ---: | ---: |
| 自述提取 | 4.98秒 | 29.87秒 |
| 22岁、高中、无编程经验、无客户人脉：生成四幕故事 | 24.38秒 | 116.34秒 |
| 45岁、本科、15年财务经验、已有同行资源：同目标生成四幕故事 | 23.19秒 | 124.59秒 |
| 同行拒绝、每周仅30分钟：反馈重规划 | 21.78秒 | 97.95秒 |

以上是精简版四项对比测试的单次结果，非速度保证；对应 `reports/live-qwen2.5-7b.json` 与 `reports/live-qwen2.5-32b.json`。后续最终代码又收紧了档案字段保留和新反馈优先级，正式入口复测另存为 `reports/production-verification.json`。

最终默认32B在正式入口复测：档案提取21.29秒、反馈重规划98.71秒，均返回200并通过字段/结构检查。年龄、每周时间、职业和“无编程经验”得到保留；拒访后第一幕改为制作样表与邀请邮件，而非将对方答复当作任务产出。本机与DGX的最终应用代码校验值一致。

两者的四幕、每幕任务数、三步结构、必要工具/示例/产出字段和第一幕时间预算均通过程序检查。两份同目标档案产生了实质不同的起步路线：新手先做 Excel 基础练习；有经验者先利用同行验证需求。32B 在拒访后改为制作样表，第一幕任务7分钟，没有把历史未反馈任务判定为失败。

7B 更快，但人工复查发现遗漏经历、把90天延长至120天、把收到回复作为可控完成标准等问题，因此正式服务选择32B。32B 仍有远期时间范围不精确、任务大小与分钟估计未必吻合、条件表达不足等问题：**连接与 JSON 结构通过不代表计划语义质量已全部通过。** 保留用户确认档案和审核草案流程，不能把生成文本直接当作已发生事实或成功承诺。

最终提取中，“没有客户联系人”仍被简化掉，资源只保留为“个人电脑”；这说明模型仍可能遗漏否定条件。确认档案时必须检查资源与限制，后续需增加语义完整性检查，当前不把这项记为通过。

## 本次修复

- 接受模型返回的数字年龄和工作年限，避免清洗时丢失。
- 用 JSON Schema 约束输出；档案核心字段允许显式 `null` 表示未知，四幕与三步任务不能缺失。Ollama 的接口能力见[官方结构化输出文档](https://docs.ollama.com/capabilities/structured-outputs)。
- 保留职业、经历、技能、资源和约束的输出位置，强调不能只在摘要提及而漏入档案。
- 限制正文长度和每幕任务数量，降低32B超过180秒超时上限的风险；旧版本32B的一次规划曾耗时173秒。
- 明确最新反馈优先于旧档案，拒绝参与的人不能默认继续提供帮助，不采用已被标为不准确的观察。
- 增加独立用户服务、权限受限的口令文件、隐藏输入的 Mac 启动器、真实模型测试和 SSH 端到端验收脚本。

## 检查范围

本地与 DGX 的功能回归、AI模拟测试、私网模型防护、认证和构建检查均完成。通过 Mac 正式隧道还检查了：认证后页面可访问、伪造身份不能跳过口令、跨来源请求返回403、未确认年龄学历的规划返回400。超时、错误 JSON、离线无外部回退、远程模型拦截由可重复的故障模拟测试覆盖；没有为测试而关闭现有 Ollama 或更改 DGX 防火墙。

手机微信键盘、长时间稳定性、多人并发和真实用户计划质量尚未验收。当前应用仍面向所有者个人使用。

## 日常维护

查看状态：`ssh dgx 'systemctl --user status butterfly-effect.service --no-pager'`

停止应用：`ssh dgx 'systemctl --user stop butterfly-effect.service'`

启动应用：`ssh dgx 'systemctl --user start butterfly-effect.service'`

停止 Mac 隧道：`ssh -S "/private/tmp/butterfly-effect-$(id -u)/dgx.sock" -O exit dgx`

连接与安全检查：在本项目目录运行 `node scripts/check-dgx-connection.mjs`。附加 `--live` 将用虚构档案进行真实提取和重规划，并更新正式入口测试记录。
