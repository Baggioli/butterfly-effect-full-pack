## ① 一页结论（对照我方故事版 / 推演）

**0 分样稿的病根：** 我们把**结构层**（台账、清单、里程碑）直接当成了**文学层**来写。正文缺幕结构、缺低谷、缺「凭什么能跨到下一步」的因果门，终局只是一行榜单。几个竞品的做法正好反过来：**结构交给规则或数据表，正文只负责写场面。**

| 产品 | 实际怎么生成「一生」（算法层） | 动人或成立的来源 | 对我方的启示 |
|---|---|---|---|
| **人生重开模拟器**（开源，已读源码） | 每过一岁执行一次：先触发天赋 → 取该年龄的事件池 → 用 include/exclude 过滤（属性阈值、**是否已发生过前置事件** EVT?、天赋） → 有高优先层就用高优先层，否则用普通池 → 加权随机 → 事件效果改属性 → 满足 branch 条件就立刻追加后果事件 → 寿命 <1 结束 → 按分数线给评价词 | 每次跃迁都能看出前因。首富是**门控链的末端**，不是随机奖励（下方有实例） | 终局的合理性靠「门」，不靠形容词 |
| **BitLife**（官方帮助页 + 商店页） | 按 Age 一年推进一次，每年弹随机事件和选择；求职晋升看属性、经验和学历；CEO 每年收到 End-of-Year Report；官方原话「businesses grow best slowly over time」；人生结束时用一条 Ribbon 一词定性，再给讣告式总结；事件全部手写 | 一年一报的节奏，加上一词给一生定性 | 每幕给一份「年终报告式」的变化，终局起一个名字；**概率和公式无公开** |
| **Fabulous Journey**（帮助中心 + Google Design 案例） | 一条多周的主题旅程 = 一组信件。每封信里有一小段科学知识，帮你识别挡在路上的阻碍，信尾要你**承诺本周做一个动作**；完成后解锁下一封信和下一个习惯；章节标题写成「In which [name] learns how to…」；第一个动作极小（起床喝水） | 读者被当成故事主角，每一章都落到一个行动 | 「幕 → 本周一步」的接口；**解锁规则细节和信件全文无公开（需登录）** |
| **MIT Future You**（arXiv 论文） | 先用 Life Story Interview 收集：重要的人、转折点、高光、低谷、人生项目、60 岁时的职业/财务/家庭愿景 → 用模板拼出一个 60 岁人设 → 每个主题追加追问，并行生成「记忆碎片」 → 合并成背景故事 → 开场固定 4 问（先说明「未来可能和你想的不一样」；「我在你这个年纪时……」梦想后来怎样了，哪些在预料之中、哪些没有；最幸福的家庭片段；人生项目是怎么开始、怎么发展的） | 用回望的口吻和语言上的连续性，让人感觉「那就是我」 | 开头和结尾用回望框架。论文自己承认：**光是想象并不足以推动行动**，需要和行为目标绑在一起 |
| 理论补位 | Dramatron 分层生成（一句话主线 → 节拍 → 正文）；storylet/QBN（内容 + 前置条件 + 效果）；Kappes & Oettingen 2011：只有正向幻想会降低行动能量，要「想象未来 + 对照现实阻碍」；McAdams 的救赎序列；峰终定律 | — | 结构、门控、阻碍、低谷和收束都有可以直接照搬的写法 |

**源码实例：人生重开的「世界首富」链**（`packages/data/src/event.xlsx` + `age.xlsx`）

1. 13–17 岁：`10565 学校举办模拟创业`。如果 `MNY>7 & INT>7`，立刻接 `20565 你的创业最成功`（SPR+1）。
2. 19–23 岁：`10606 你对金融和计算机都十分擅长`（前提是读过相关专业，EVT?[10579–10584]）。
3. **22 岁，走高优先层**：`10608 你前往硅谷创业`。门槛是 `MNY>8` 并且经历过 10606 或 10565。
4. 23–24 岁 `10613 创业非常成功` → 29–31 岁 `10620 公司上市`（grade 2）→ 36–49 岁 `10628 收购了好几家创业公司` → 41–50 岁 `10646 你成为了世界首富`（grade 3）。这四步**全部要求经历过 10608**，并且都用 exclude 防止重复。
5. 全部 1766 个事件按 grade 0/1/2/3 分布为 1279/240/163/84（约 72%/14%/9%/5%）；抽天赋的基础权重是 889/100/10/1（‰）。

**启示：** 人生重开每年只写一句话，但「门 → 资格 → 稀有终局」这套骨架让人信服。我们要抄的是骨架，**它那种一句话流水账的文风不抄**。我方正文应当是「一道门写成一个场面」。

**给我方的 5 条结论：**
1. **结构层和文学层分开。** 规则层产出幕骨架、门控链、数字和代价；LLM 只按骨架写场面。正文里不得出现台账、清单、文件名这类结构层名词（呼应硬条件 7）。
2. **宏大终局 = 门控链的末端。** 首富链要倒推出 5–7 道门（例：第一个付费客户 → 可复制交付 → 规模化 → 拿到资本 → 并购或上市 → 上榜）。每道门用一个「被看见的场面」来证明，比如第一次有人付钱、第一次有同行来抄，不靠罗列。
3. **情绪曲线强制成形。** 中段至少有 1 个带代价的低谷，然后写「转化」，而不是「咬牙坚持」。峰值放在倒数第二幕；末幕安静收束，回扣开篇出现过的物件或场景。
4. **回望框架加现实对照。** 开头和结尾用「终局时的你」的口吻（Future You），中间各幕按「想要的画面 → 挡路的现实 → 行动 → 变化/代价」推进（mental contrasting）。这就是我们四元素的情绪化写法。
5. **执行力落在幕尾的「这一幕的第一步」**（Fabulous 信尾承诺），再映射到近端的今日/本周任务卡（plan 和 proj 同源）。不要把任务清单塞进正文中段。

## ② 叙事算法可抄点（8 条，可以直接注入提示词或规则层）

### K1 分层生成：一句话主线 → 幕节拍表 → 逐幕正文
- **借鉴：** Dramatron（DeepMind，CHI 2023）。它先生成 log line，再生成角色和情节节拍，最后生成正文。中间那层节拍表让末幕能闭合开幕埋下的伏笔。
- **怎么写进我方：**
  - Step 1（规则 + LLM）：写一句话主线，必须包含起点处境、终局画面和核心矛盾。
  - Step 2（**规则层定数字**）：输出 beats JSON，每幕 `{幕名, 年份区间, 要跨的门, 场面, 挡路现实, 行动, 变化, 代价, 情绪值(-3..+3), 伏笔/回收}`。
  - Step 3（LLM）：逐幕写 300–500 字。输入只给「主线 + 本幕 beat + 前一幕摘要」，**禁止新增数字**。
- **不抄：** 剧本对白格式；为了戏剧冲突硬造的反派。

### K2 门控事件链（前置事件 + 阈值 → 解锁）
- **借鉴：** 人生重开 `include: (MNY>8)&(EVT?[...])` 加 exclude 防重复；BitLife 求职晋升看属性、经验和学历；Emily Short / Failbetter 的 storylet（内容 + 前置条件 + 效果）。
- **怎么写进我方：** 规则层从终局倒推 5–7 道门，每道门写成 `{门名, 解锁条件(能力/资源/证据阈值，来自规则层), 解锁后效果, 证明场面}`。提示词加一句：「只能按门的顺序推进，不得跳门；每跨过一道门，必须写出一个让旁人看见的具体场面作为证明。」以 Micheal 为原型时，门可以挂在水循环技术壁垒 → 第一个付费水务客户 → 逸泓智能产品化……这条线上。
- **不抄：** 修仙、玄幻、恶搞类事件；随机出生；死亡结局；「家里资金人脉」这类外挂式成功的解释。

### K3 稀有度分层与高光配额
- **借鉴：** 人生重开事件分 4 级（约 72/14/9/5%），天赋抽取权重 889/100/10/1‰，终局事件是 grade 3；也对应峰终定律（Redelmeier & Kahneman 1996）。
- **怎么写进我方：** 规则层给每幕打 `tier: 日常|转折|高光|终局`，每篇高光最多 2 处，终局级只出现 1 次。外部机遇（政策、大客户）可以出现，但要写成「如果出现……」，不能当主因，成因必须落在主角自己的行动上，这和「模拟非承诺」口径一致。
- **不抄：** 抽卡、十连、稀有度配色等游戏化包装；用运气解释成功。

### K4 分支的即刻后果与延迟回收
- **借鉴：** 人生重开的 `branch`：事件发生后，如果满足条件，立刻追加一个后果事件（例：模拟创业 → `MNY>7&INT>7` → 「你的创业最成功」）；BitLife 的选择会影响以后能走哪些路。
- **怎么写进我方：** 每一幕的关键选择都写两层后果：「当场后果」和「延迟后果（在下一幕或下下幕回收）」。beat 里加 `setup_id / payoff_id` 字段，自检时要求每个 setup 都被回收。
- **不抄：** 死亡、犯罪、入狱类分支；为了刺激而写的反转。

### K5 情绪曲线：低谷 → 救赎，峰值在后，安静收束
- **借鉴：** McAdams 的救赎序列（坏事被转化成好结果，和幸福感、生成性相关）；峰终定律；BitLife 用 Ribbon 一词定性一生；80亿分之一的终局回顾。
- **怎么写进我方：** 规则层校验情绪值序列：中段至少一处 ≤-2，紧接着的一幕必须写「这次低谷换来了什么」，不能只写坚持；峰值放在倒数第二幕；末幕情绪回落到 +1~+2，回扣开篇的物件或场景，并给「这一程起一个名字」（替代 Ribbon）。失败一律用「卡住、代价、绕路」来写，不出现「你失败了」。
- **不抄：** 墓碑、讣告、评级词（人生重开的「地狱…传说」、BitLife 的 Ribbon 收藏）；任何疗效说法。

### K6 未来记忆回望框架
- **借鉴：** MIT Future You：Life Story 字段 → 60 岁人设 → 记忆碎片 → 开场 4 问，以及「我在你这个年纪时……」这种语言连续性线索。
- **怎么写进我方：** 开头不超过 150 字，用终局时的「你」的口吻写：「我在你这个年纪时……」，提到 1 个转折、1 个低谷、1 个人生项目，并**在故事内自然说出**「后来的路和当时想的不太一样」，相当于在故事里体现「模拟非承诺」。结尾再回到当下，引出第一步。输入字段复用现有建档（重要的人、转折、项目）；缺了就省略，**不加长问卷**。
- **不抄：** 年龄化头像；固定 60 岁；把「降低焦虑、提升未来自我连续性」当卖点（只作内部参考）。

### K7 幻想与现实对照（每一幕的内部结构）
- **借鉴：** Kappes & Oettingen 2011：只有正向幻想会降低行动能量；mental contrasting 是先想象未来，再对照现实中的阻碍。Future You 论文也承认，光有想象不一定带来行动。
- **怎么写进我方：** 每一幕固定按「想要的画面 → 挡路的现实（具体到人、钱、技术、时间）→ 行动 → 变化 / 代价」来写。这正是处境·行动·变化·代价四元素的情绪化版本。终局越大，前面写出的阻碍就要越具体，这直接回应「不真实」这条批评。
- **不抄：** WOOP 的品牌名和教练、疗法话术。

### K8 章节信件 + 「这一幕的第一步」
- **借鉴：** Fabulous Journey：章节标题写成「In which [name] learns how to…」，每封信末承诺一个本周动作，第一步极小，完成后才解锁下一章。
- **怎么写进我方：** 幕标题用「第 N 幕 · {年份}：在这一幕里，{名字}学会 / 走到……」。每幕最后一句给「这一幕的第一步」，由规则层映射到近端的今日 / 本周任务（和 plan 同一来源）。第一幕的第一步必须小到今天就能做完，例如「给一位老客户打电话，问他最头疼的水质问题」，写成生活动作，不写清单。
- **不抄：** Fabulous 的插画、人物和文案；科学疗效声明；付费解锁节奏。

**可以直接粘进系统提示词的规则片段（草案）：**
```
你只负责把给定的幕节拍写成场面，不新增任何数字、不跳过任何一道门。
每一幕按「想要的画面→挡路的现实→行动→变化/代价」推进；每跨一道门写一个被旁人看见的具体场面。
全篇至少一个低谷，低谷后写它换来了什么；高光不超过两处；最后一幕回扣开头出现过的物件或场景。
开头用"我在你这个年纪时……"的回望口吻，并在故事里自然说出"后来的路和当时想的不太一样"。
正文禁止出现：清单、台账、文件名、项目编号；禁止"预测/预言/注定/命运/你失败了"。
每幕最后一句写"这一幕的第一步"，要是今天就能做的一件小事。
```

**自检清单（规则层可以自动判定）：** 门数 5–7 且按序跨越；结构层名词命中 0；情绪值中段 ≤-2 至少 1 处；高光 ≤2；setup 全部回收；末幕回扣开篇；每幕都有第一步；禁词 0。

## ③ 相对旧竞品文档的新增
- 旧文只到 UI 和定位层：人生重开只有界面流程和 20 点分配，BitLife 只有定位，Future You 只有 N=344 和「60 岁未来记忆」。本文新增的是**算法层**：

  - 首富链 7 个事件的真实门控和年龄窗口；
  - 稀有度和权重的实际分布；
  - Future You 的生成管线和开场 4 问；
  - BitLife 官方公开的晋升、年终报告、Ribbon 机制；
  - Fabulous 的信件 → 承诺 → 解锁结构。
- 新引入的理论来源：Dramatron 分层生成、storylet/QBN、Kappes & Oettingen 2011、McAdams 救赎序列、峰终定律。
- 新产出：8 条可注入点，以及提示词片段和自检清单；对照表见 `竞品-人生推演叙事算法-v0.csv`。

## ④ 无公开 / 限制
- BitLife：事件概率、晋升公式、Karma 权重、事件总数——**无公开**（帮助页原话是「We can't give too much away」）。fandom wiki 上的数据未经核实，本文没有采用。
