## 1. 结论

| 项 | 建议 |
|----|------|
| 是否纳入可投放 | **纳入，作为可选冷启动支路**，不替换「聊天/语音建档」主路径 |
| 排期 | **P1**（本轮演示/闭测主链路稳定后再做）；开发**勿抢先改主链路** |
| MVP 形态 | **零对接**：复制提示词 → 用户在 ChatGPT/Claude/豆包等粘贴 → 把结果贴回本产品解析 |
| 不做（本阶段） | 官方 API 拉取他方记忆、自动登录他方账号、强制问卷加长 |

**理由（利）**：用户已在他方 AI 积累上下文，比从零聊天更快建立「够深」的起点，直接服务「用户理解不够深」痛点；工程量小、可先验证转化。  
**理由（弊/风险）**：跳出 App 有摩擦；粘贴质量参差；隐私与同意须明示；与 demo/建档状态机要小心，避免绕过同意或污染演示数据。

## 2. 入口设计（建议）

**位置（建档前/建档中二选一，推荐 A）**

- **A. 同意页通过后、开聊前**：次按钮「我已有常用 AI，先导入画像」+ 主按钮「直接开始聊」  
- **B. 建档聊到一半**：弱入口「改用已有 AI 总结」（易打断对话，次选）

**交互（MVP 三步）**

1. 展示「复制提示词」+ 说明适用：ChatGPT / Claude / 豆包 / 通义等（有长期对话更佳）  
2. 大文本框「把 AI 的回复贴这里」+「用这份画像继续」  
3. 解析成功 → 预填角色卡（可编辑确认）→ 进故事/推演；失败 → 回退主路径开聊，不挡路

**文案原则**

- 标明：内容由你从他方 AI 粘贴，我们按敏感信息同意处理；可删改后再确认  
- 禁用「预测/命运」等法务词；不暗示他方 AI「更懂你所以算命」  
- 演示模式（`?demo=1`）：入口可灰显或隐藏，避免演示串真实粘贴数据

**验收（产品侧最小）**

- 主路径（直接开聊）零回归  
- 粘贴合法结构化文本 → 角色卡字段可见且可改  
- 空粘贴 / 乱码 → 友好提示并回主路径  
- 埋点：入口曝光、复制提示词、提交粘贴、解析成功/失败、确认进故事

## 3. 提示词方案（给用户复制）

### 3.1 主提示词（**默认**）

```text
请根据我们过往的对话，整理一份「关于我」的冷启动画像，供另一款人生规划/推演产品使用。
要求：
1) 只写你有依据的信息；不确定就写「未知」，不要编造。
2) 用下面固定小标题输出（每个标题下用短句或条目，中文）：
【基本】称呼偏好、年龄段、城市、职业/身份、家庭或重要关系（可知的）
【现状】正在做的事、资源与约束（时间/钱/健康/精力）
【目标】近 3–12 个月最想达成的 1–3 件事（尽量具体、可验证）
【卡点】反复出现的困难、容易放弃的触发点
【风格】做决定的习惯、喜欢怎样被提醒或拆任务
【忌讳】不希望被怎样评价或施压（若未知写未知）
3) 全文控制在 600–900 字；不要鸡汤，不要预测未来成败。
4) 末尾加一行：依据来自对话中的哪些主题（列 3–5 个关键词即可）。
```

### 3.2 精简版（嫌长 / 二次备选）

```text
根据我们的聊天，用条目列出：我是谁、现在处境、近一年目标、主要卡点、做事风格。不确定写「未知」，勿编造，300字内，不要预测成败。
```

### 3.3 补全版（主提示词结果太瘦时，二次粘贴）

```text
上一份画像偏薄。请只补充这几项（仍勿编造）：职业细节与收入大致区间（可写区间或「不愿透露」）、每周可投入小时数、已尝试过但效果差的方法、最在意的他人评价来源。用同样小标题追加，不超过 400 字。
```

## 4. 解析与落库（给开发的产品口径，未开工）

- 优先认 `【基本】…【忌讳】` 标题；认不出则整段进「自由备注」，仍允许用户手改角色卡  
- 映射到现有建档字段：身份/城市/目标/约束/风格标签；映射不上的进备注，**不阻断**确认  
- 不自动当「已校准收入区间」；收入仍走现有来源规则与免责  
- 粘贴原文默认用户可一键删除；日志不落原文（与可投放「对话原文不进日志」一致）
