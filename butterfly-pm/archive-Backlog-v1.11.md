## 1. 一页「可投放市场」定义

**一句话**：陌生的真实用户用自己的手机打开链接，不需要我们陪同，就能在约 5 分钟内完成「倾诉 → 确认角色卡 → 四幕故事 → 领到今天第一件任务」；7 天后换设备登录，数据仍然在；出问题时不会丢资料，也不会被误导。

### 必须有（上线门槛）
1. **主链路稳定**：建档 → 角色卡确认 → 展开故事 → 今日/7 天任务，端到端可用；“展开故事”失败可重试且不丢角色卡。
2. **语音为主、文字兜底**：系统先出声提问，停顿后自动接话；麦克风被拒、断网、识别失败时自动可用文字完成全流程。音色经 Micheal 最终确认。
3. **真机可用**：iOS Safari、Android Chrome、微信内置浏览器三端通过麦克风授权、连续播放、软键盘、底栏与安全区验收（375/390/430px）。
4. **账号与数据**：服务端账号采用**手机号验证码**（Micheal 已定；微信授权首发不做、后补）+ 服务端存储；换设备可找回；用户可导出、可一键删除全部数据。替代现在仅靠浏览器 localStorage 的方式。
5. **公网可承载**：与原 DGX 现网隔离的独立部署。**闭测/真模型复测走私有 DGX（独立目录与端口）**；**公网正式版使用合规可用的云端推理，不把公网流量压在私有 DGX 上**（Micheal 2026-10-24 已拍板）。内测仍分波次（建议每天 20–30 人）；高峰排队+超时可重试。候补 1000 / 总激活 300 是规模目标。
6. **合规与安全底线**：用户协议与隐私政策（**抬头：逸泓智能**）、未成年人提示、心理危机关键词识别与求助热线指引、不承诺命运预测/成功概率；上线主体与备案挂**逸泓智能**（Micheal 已定）；ICP 与生成式 AI 服务相关备案按此主体推进。
7. **可观测**：基础埋点（建档完成率、故事生成成功率与耗时、首任务领取率、D1/D7 回访）和错误日志，不记录录音、不把对话原文写进日志。
8. **界面口径**：不出现 AI、DGX、Ollama 等实现术语；未知信息保持未知，推测不冒充事实。

### 可以以后做
- 微信原生小程序工程与审核发布
- 完整数据导入、跨设备历史迁移旧 localStorage 数据
- 日/周/月计划全量、成果库、复盘可视化
- 付费体系上线（首发前只做定价假设验证，由市场给出）
- 社区、多旅程/多角色（分享卡、第7天复盘已升至公网 P0；闭测可不带分享卡）
- 声音克隆或多音色选择、方言识别

## 3. 给开发的验收清单

### A. 主链路
- [ ] A1 10 名真人（非合成音频）各自从首页建档到领取第一件任务，成功 ≥ 9 人；记录每人耗时
- [x] A2 「展开故事」连续 20 次真实生成 0 失败（**A2#3：20/20**，合成画像；超时/断网可重试与角色卡不丢仍须在人为故障用例中保持）
- [ ] A3 建档中位时长 ≤ 4 分钟。故事生成以 A2#3 为准：**P50≈111s，P90≈117s**；进度可写「大约两分钟」；超时保持 300s。**不强制 30 秒**；公网切云端后重测
- [ ] A4 第一章包含今天 + 7 天任务，每条有步骤、工具、用时、产出、完成标准
- [ ] A5 年龄/学历/时间缺失时故事明确写“未知”，不伪造默认值

### B. 语音
- [ ] B1 系统每轮先出声，播完再开麦；暂停/切文字会取消待播音频并释放麦克风
- [ ] B2 静音、设备未接通、字幕类幻觉不推进建档（422 不写入）
- [ ] B3 真人样本 ≥ 5 人 × 各 5 轮，记录关键信息（年龄、学历、职业、目标）识别错误数；区分真人与合成结果
- [ ] B4 麦克风拒绝、断网、语音服务故障时，文字可完成全流程
- [ ] B5 Micheal 书面确认最终音色、语速、等待时长

### C. 真机
- [ ] C1 iOS Safari / Android Chrome / 微信内置浏览器：麦克风授权、连续多轮播放与录音
- [ ] C2 375 / 390 / 430px 与短视口：软键盘、底栏、安全区不遮挡输入框和按钮
- [ ] C3 切后台、锁屏、来电后回到页面，不自动开麦，状态可恢复
- [ ] C4 蓝牙耳机连接/断开时自动切换设备

### D. 账号与数据
- [ ] D1 注册/登录可用；A 设备建档后在 B 设备登录可看到角色卡、故事、任务与历史
- [ ] D2 导出全部个人数据；一键删除后服务端不可再读到
- [ ] D3 不保存录音；日志不含对话原文与个人信息
- [ ] D4 data-private 不进入仓库、构建产物或部署包

### E. 部署与安全
- [ ] E1 新部署使用独立目录/端口/服务名，原 DGX 应用与 443/Funnel 未被改动
- [ ] E2 `npm test`、`npm run build`、`npm run validate` 通过
- [ ] E3 按「同时约 1 个展开故事」设计排队；分波次（每天 20–30 人）压测时主链路成功率不下降，超时走可重试
- [ ] E4 界面全文检索无 AI/DGX/Ollama 等术语

### F. 不能算作验收的情况
- 合成语音或示例任务通过，不等于真人验收
- 接口返回成功或“已播放”，不等于用户真的听到、完成了一轮
- 一次手动跑通，不等于 A2 的连续稳定性

### G. 法务投放前阻塞（公网前必须全绿）
- [ ] G1 登录/注册页默认不勾选，用户须主动勾选同意《用户协议》与《隐私政策》后方可继续
- [ ] G2 收集敏感个人信息前有单独同意（目的、范围说明 + 可拒绝；拒绝后文字路径仍可用）
- [ ] G3 产品与协议中未成年人表述一致：未满 14 周岁按儿童个人信息保护；未满 18 周岁须监护人同意与指导
- [ ] G4 危机关键词触发后展示定稿热线（见协议 v0.2），可点击/可复制，并声明不构成诊疗
- [ ] G5 应用内「导出全部数据」「删除全部数据」「注销账号」入口可点，并完成一轮真机验收
- [ ] G6 订阅/付费相关文案在正式收费前统一为「本期不收费」；上线收费前再经法务审
- [ ] G7 协议与隐私政策展示主体证照信息与有效联系方式（Micheal 补齐后替换草稿占位）
- [ ] G8 隐私政策列明短信、云端推理、云存储等受托方名称（供应商确定后）
