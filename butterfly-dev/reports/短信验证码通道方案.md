# 短信验证码通道方案（P0-5 账号）

面向：蝴蝶效应公网正式版 · 上线主体 **逸泓智能**  
首发登录：**手机号 + 短信验证码**（微信授权后补，不做首发）

---

## 1. MVP 推荐结论

**默认采用阿里云短信（国内短信 / 验证码模板）。**

理由（闭测 → 首发）：

- 国内到达率与签名/模板审核路径成熟，企业主体（逸泓智能）报备流程清晰；
- Node / 服务端 SDK 与 REST 文档完整，和后续账号服务同云（若选阿里云部署）运维简单；
- 单价可接受：验证码类常见约 **¥0.04–0.055 / 条** 量级（以控制台实时报价为准），候补 1000、激活 300 的内测规模成本可控；
- 支持频率限制、回执、模板变量，满足「不把完整手机号+验证码打进同一条日志」的落地方式。

备选：腾讯云短信（若公网主体与腾讯云/微信生态绑定更深时再评估切换，接口形状类似，迁移成本低）。

## 2. 简要比对

| 维度 | 阿里云短信 | 腾讯云短信 | 其他（华为云 / 云片等） |
|------|------------|------------|-------------------------|
| 价格球park | 验证码约 4–5.5 分/条 | 验证码约 4–5.5 分/条 | 参差；中小通道常更便宜但稳定性与合规支持弱 |
| 签名报备 | 需企业资质；签名+模板审核（通常 1–2 工作日） | 同左，企业签名 | 部分要求更严或只适合营销 |
| 到达率 | 三大运营商直连/优质通道，验证码场景稳定 | 同左 | 需压测；晚高峰可能抖 |
| SDK | `@alicloud/dysmsapi20170525` 或 OpenAPI | `tencentcloud-sdk-nodejs` SMS | 各异 |
| 合规 | 实名、签名与模板审核、停用词；配合《个人信息保护法》最小化 | 同左 | 需单独核验是否可挂逸泓智能 |

**不推荐**：个人通道、境外汇聚短信、未报备签名的「通知类」滥发——审核和封号风险高，不适合登录 OTP。

## 3. 架构（服务端）

```
客户端                账号 API（公网）              短信供应商
  │  POST /api/auth/send-code  { phone }              │
  │───────────────────────────►│  校验格式/限流         │
  │                            │  生成 6 位码，哈希入库  │
  │                            │  调 SendSms ──────────►│
  │  { ok, cooldownSec } ◄─────│                        │
  │                            │                        │
  │  POST /api/auth/verify-code { phone, code }         │
  │───────────────────────────►│  校验 TTL / 次数        │
  │  { token / session } ◄─────│  建立用户与档案绑定     │
```

### 3.1 API 约定（实现阶段）

| 接口 | 行为 |
|------|------|
| `POST /api/auth/send-code` | 校验 `+86` 手机号；同一号 **60s** 冷却；同一号 **1 小时 ≤ 5 次**；同一 IP **1 小时 ≤ 20 次**；写验证码记录（只存 **HMAC/哈希**，不存明文码）；调供应商发送 |
| `POST /api/auth/verify-code` | 校验码；**TTL 5 分钟**；错误 **≤ 5 次** 后作废并要求重发；成功签发会话（HttpOnly Cookie 或 Bearer），并创建/绑定服务端用户档案 |

### 3.2 安全与隐私

- **禁止**把「完整手机号 + 明文验证码」打进同一条应用日志或监控字段；日志最多保留手机号脱敏（如 `138****5678`）与 `requestId`。
- 验证码仅存哈希（如 `HMAC-SHA256(code, AUTH_OTP_PEPPER)`）+ 过期时间 + 尝试次数。
- 发送回执与供应商 `bizId` 可存，用于客服排障，不含验证码明文。
- 传输全程 HTTPS；验证码接口不走 CDN 缓存。

### 3.3 环境变量（名称 only，无真实密钥）

| 变量名 | 用途 |
|--------|------|
| `SMS_PROVIDER` | `aliyun`（默认）或 `tencent` |
| `SMS_ACCESS_KEY_ID` | 供应商 AccessKey Id |
| `SMS_ACCESS_KEY_SECRET` | 供应商 AccessKey Secret |
| `SMS_SIGN_NAME` | 已审核签名，如「逸泓智能」 |
| `SMS_TEMPLATE_CODE` | 验证码模板 CODE |
| `SMS_REGION` | 如 `cn-hangzhou` / `ap-guangzhou` |
| `AUTH_OTP_PEPPER` | 服务端哈希胡椒 |
| `AUTH_OTP_TTL_SEC` | 默认 `300` |
| `AUTH_OTP_COOLDOWN_SEC` | 默认 `60` |
| `AUTH_SESSION_SECRET` | 会话签名密钥 |

密钥由 Micheal **单独**下发到部署环境，不进仓库、不进群、不进交接包的 `data-private` 以外的共享路径。

## 4. 上线前清单（逸泓智能）

1. 用逸泓智能营业执照完成阿里云（或腾讯云）实名与短信服务开通；  
2. 申请签名「逸泓智能」+ 验证码模板（文案示例：`您的验证码为${code}，5分钟内有效，请勿泄露。`）；  
3. 隐私政策 / 用户协议写明：手机号用于登录与安全验证，保留期限与注销方式；  
4. 闭测可先用测试号白名单；公网前打开到达率与失败码监控；  
5. **微信授权登录**列为 P1：首发不做；接口预留 `provider=wechat` 即可。

## 5. 与现有产品约束的关系

- 替换 localStorage 单机档案：验证码登录成功后，角色卡 / 故事 / 任务写入**服务端账号存储**（P0-5），换设备可恢复。  
- 公网推理走合规云端；短信通道与推理供应商解耦，本方案不依赖 DGX。  
- DeepSeek / 其他模型 Key 与短信 Key 分权分环境，互不复用。
